# 6단계 화면 구성 제안

2026-09-18 작성, 2026-09-19 승인 범위 갱신. **화면 흐름은 작업 방향으로 승인되었고 실제 서비스 UI에는 적용하지 않았다.** [통합 검수](../reviews/core-flow-pre-design.md)의 남은 제한을 전제로 한다. 사용자 후속 요청에 따라 [두 시각 방향·대표 동작](stage-6-visual-directions.md) 확인 → 디자인 통합 → 같은 흐름 재검수 순서다. 최종 디자인·출시 승인은 아니다.

## 중심 구조

모바일은 ‘시작 → 추천·조건 수정 → 계획 선택·길찾기’ 3개 구역으로 정리한다. 별도 로그인·페이지 이동을 필수로 만들지 않고 기존 입력/조정/선택 상태를 보존한다. 지도보다 ‘왜 이 계획인지, 무엇을 바꿀 수 있는지, 이제 무엇을 해야 하는지’를 먼저 읽게 한다.

데스크톱은 2열을 기본으로 한다. 왼쪽 약 300~340px에는 입력·출발지·적용 조건을, 오른쪽 가변 폭에는 추천/비교/선택 내용을 둔다. 지도·전체 예측은 보조 영역으로 접거나 펼친다. 3열을 강제로 만들지 않으며 좁은 창에서는 모바일 순서로 돌아간다.

## 1. 시작

모바일 순서:

1. 짧은 안내 ‘오늘은 어디에서 조금 덜 붐비게 걸을까요?’와 현재 한강공원 5곳 산책 지원 표시.
2. 자연어 요청 입력. 목적지 미정 또는 이미 정한 목적지를 같은 입력/직접 조건 영역에서 다룬다. 정확한 도착시각을 첫 필수 질문으로 요구하지 않는다.
3. ‘지금 출발 / 방문 시간대 직접 입력’을 명시적으로 선택. **지금 출발**이면 출발지와 TMAP ETA를 사용한다. 시간대 입력이면 이동시간 미반영을 표시한다. 미래 출발을 지원하는 것처럼 보이지 않게 한다.
4. 현재 위치 또는 출발역 검색. 권한 팝업은 버튼을 누를 때만 요청한다. 위치 실패 때 검색창이 같은 자리에서 남는다. 자동 도착 모드의 추천 전에는 출발지 선택이 필요하다.
5. ‘이 조건으로 추천받기’ 하나를 주 행동으로 둔다. 직접 조건 입력은 대안이다. 체류시간 생략 시 60분을 몰래 채우지 않는다. 자연어/수동 기본 시간 범위가 제안값이라는 사실과 수정 방법을 드러낸다.
6. 재방문이면 ‘이전 계획 이어보기’ 요약을 먼저 제공하고 새로 시작/삭제를 구분한다. 오래된 ETA·혼잡을 지금 결과로 보여주지 않는다.

입력 문장의 OpenAI 전달, 출발 좌표의 TMAP/선택 지도 전달, 같은 브라우저 7일 보관 안내는 관련 행동 근처에 짧게 둔다. API 키·모델·Redis 같은 구현 항목은 제품의 기본 입력 흐름에서 빼고 운영 문서에 둔다.

## 2. 추천·조건 수정

모바일 순서:

1. 적용 조건 요약: 출발지, 지금 출발/직접 시간대, 체류, 혼잡 선호. 처음 조건과 나중의 고정·제외를 구분한다. 최초 조건의 변경과 추가 고정 해제가 다른 행동임을 라벨로 알린다.
2. 주 추천 카드: 장소 → 도착/체류 종료 → 대중교통 소요시간·도보 포함/접근 지점 → 추천 이유 한 문장 → 평가 표본. 확정적 ‘한산 보장’이나 근거 없는 분 단위 공식 혼잡을 만들지 않는다.
3. ‘이 계획 선택’을 주 행동으로. ‘망원으로 고정’, ‘18:23 고정’, ‘이번에는 제외’처럼 적용 값을 버튼에 쓴다. 지도 길찾기는 아직 보이지 않는다.
4. 다른 선택 및 원래 계획. 엔진이 반환한 후보만 사용한다. 원래 장소·시각이 있을 때만 유지/변경·차이를 표현한다. 목적지 미정에서 시작했으면 원래 계획·0분 변경을 만들지 않는다. 후보 수를 채우기 위해 선호/필수 조건을 벗어난 카드를 임의 추가하지 않는다.
5. 근거 상세: 공식 예측 시각·단계와 숨맵 인구 추정, 원자료/수신/비교 시각. 카드 핵심에는 자료 상태를 두고 세 시각의 상세는 접어도 라벨을 없애지 않는다. ‘34분 전’은 어느 확인 시점 기준인지 명시한다.
6. 전체 예측·위치 탐색은 보조 행동. 기존 공식 집계 영역 지도와 그래프를 유지한다. 지도 선택이 계획 조건을 바꾸지 않는다.

조건 수정 후에는 무엇이 바뀌었는지 요약하고 재비교 중/완료 상태를 알린다. 이전 결과는 이전 조건의 결과로 표시하고 선택을 막는다. 포커스를 결과 제목으로 옮기거나 결과 업데이트를 안내해 수정 결과를 놓치지 않게 한다. 고정으로 결과가 없어져도 자동 해제하지 않는다.

## 3. 계획 선택·길찾기

확정 전: 출발지→공원 접근 지점, 예상 도착/체류/혼잡 선호 충족 여부를 검토하고 같은 선택의 자료를 다시 확인한다. 자료가 달라졌거나 만료되면 변화/재확인 행동을 표시한다. 현재 재확인·확정 규칙을 유지한다.

확정 후: ‘계획 확정·이 브라우저에 저장’ 요약 아래에 **네이버지도로 길찾기 / 카카오맵으로 길찾기**를 크게 배치한다. 두 버튼은 출발지와 TMAP에 사용한 동일 accessPoint를 재사용한다. 상세 경로는 지도 앱이 다시 계산한다.

- 모바일: 기존 공식 앱 연결 우선. 네이버 미설치/실패는 설치 안내, 카카오는 공식 웹 대안.
- 데스크톱: 네이버 모바일 설치 안내, 카카오 웹 길찾기. 검증되지 않은 네이버 웹 경로 파라미터를 새로 만들지 않는다.
- 재방문: 이전에 확정한 계획임을 표시하고 지도 실행 가능. 새 혼잡 추천은 ‘현재 자료로 다시 비교’로 구분한다. 위치가 이동했을 수 있으므로 저장 출발지를 다시 확인할 수 있게 한다.
- 같은 단계 안에서 ‘다른 계획 보기’와 ‘저장 내용 삭제’를 별도로 제공한다.

## 상태별 화면·행동

| 상태 | 화면에서 먼저 보여줄 것 | 다음 행동과 보존 규칙 |
|---|---|---|
| 위치 권한 거절/시간 초과 | ‘위치를 확인할 수 없어요. 출발역으로 계속할 수 있어요.’ | 출발역 검색 유지. 권한 재요청 반복 없음 |
| 후보 없음: 조건 충돌 | 충돌한 고정·제외/허용 범위 이름 | 사용자가 특정 추가 고정/제외를 해제. 자동 완화 없음 |
| 도착이 첫 예측보다 빠름/체류 끝 누락 | 예상 도착/종료와 제공 예측 범위를 분리 | 직접 방문 시간대 변경 또는 자료 재확인. 현재 관측 대입·ETA 자동 이동 없음 |
| 30~60분 전 자료 | ‘지연 자료에 포함된 미래 예측’과 원자료 시각 | 명시적으로 허용했을 때만 참고 비교. 현재 상태로 표현하지 않음 |
| 60분 초과/대체/수신 지연 | 추천 보류와 이유 | 입력·조건 유지, 자료만 다시 확인. 과거 카드를 정상 추천으로 노출하지 않음 |
| AI 해석 실패/제한 | 문장은 보존됐다는 안내 | 직접 조건 입력. 자동으로 더 비싼 모델이나 다른 AI에 전달하지 않음 |
| AI 설명 실패 | 추천과 계산된 근거 유지 | 기존 코드 설명 사용. 해석 실패와 구분 |
| TMAP 실패/Free 한도/만료 | 자동 도착 비교 보류와 원인 | 출발지 유지, 직접 방문 시간대 입력. 0분/직선거리 ETA를 만들지 않음 |
| 서울시 API 실패 | 최신 추천을 만들 수 없다는 안내 | 기존 품질 정책 내 자료만 사용. 저장된 확정 계획의 외부 지도 실행은 별도 유지 |
| 혼잡 선호 초과/불확실 | 추천 성공 색과 구분한 명시적 ‘선호 초과/불확실’ | 필수 조건은 유지. 참고 후보 선택 전에 해당 제한을 다시 표시 |
| 지도 앱 미설치/실행 실패 | 공식 설치/웹 대안 | 출발·도착 재입력 없이 가능한 링크 유지. 실제 설치를 감지했다고 단정하지 않음 |
| 저장 실패/차단·저장 만료 | 현재 사용은 가능하지만 재방문 보존이 안 된다는 안내 | 현재 화면 유지, 명시적 삭제/새 시작 |
| 로딩·연속 조작 | 현재 수행 단계, 중복 실행 불가, 입력 보존 | 기존 요청 순서/만료 보호 유지. 무한 자동 재시도 없음 |

## 디자인 변경과 기능 수정의 경계

이번 준비 작업에서 앱 기능 수정 **0건**, API 계약·알고리즘·모델·비용 한도 변경 **0건**이다.

승인 후 디자인: 색·서체·간격·카드·위계·반응형 배치·접기/펼치기·조건 라벨·화면 이동/포커스·오류 문구. 입력순서와 기본 진입 모드를 손보는 경우에도 자연어/수동/자동 도착 모드의 상태 의미와 사용자 조건을 유지한다. 예측 부족 등 복구 행동은 기존 상태 전이에 연결한다.

별도 기능 변경으로 보고할 것: 해석 schema/기본값, 추천 정렬/후보 구성, 시각·보간·신선도 정책, 저장 데이터/만료 정책, 호출 횟수/쿼터, 새 위치검색·지도 API. 디자인 편의를 이유로 바꾸지 않는다.

## 적용 후 같은 흐름 재검수

1. 별도 시험 상태에서 정확한 도착시각 없이 시작→출발역 선택→실제 자료 추천→장소/시각 고정→재추천→선택/확정→외부 지도 실행. 실제 다중 API 전체 UI의 공백을 여기서 닫는다. GPS·앱 설치 분기는 실제 휴대폰에서 별도 확인한다.
2. 전후 동일 fixture에서 조건·후보 ID·정렬·시각·근거·요청 횟수가 같은지 비교한다. 기존 117개 검사, 타입·린트·빌드와 영향받은 화면 검사를 수행한다. 디자인 때문에 API를 반복 소비하지 않는다.
3. 새로고침·탭 재방문·저장 삭제, 오래된 저장 계획, 연속 조건 수정, 실패/빈 결과/선호 불확실, 키보드/모바일 320·390px 및 데스크톱 검수.
4. 원자료/예측/계산 시각 구분·API 키 번들 노출·같은 세션 외 캐시 격리·예산 제어가 유지되는지 변경 범위에 맞춰 확인한다. 실제 API 테스트 전에 남은 TMAP Free/AI 원장을 확인한다. 한도 확대는 자동으로 하지 않는다.
5. 사용자에게 버전·배포·실연동/모의/실기기 상태를 다시 보고한다. 이 준비안 승인이나 디자인 자체 완료를 최종 기능 검수 승인으로 바꾸지 않는다.

## 처음 사용하는 사람 검수

현재 실제 처음 쓰는 사람의 관찰은 **아직 수행하지 않았다**. 개발자 자체 검수와 실제 사용자 검수를 분리한다. 디자인 적용 후 가능하면 처음 쓰는 사람 1~3명에게 사전 조작 설명 없이 아래 과제만 준다. 외부 연락은 승인 없이 보내지 않는다.

- ‘지금 한 시간 걷고 싶고 붐비는 곳은 피하고 싶다’는 상황에서 시작하고, 어디를 왜 추천하는지 자기 말로 설명하기.
- 추천 중 한 장소를 고정하거나 제외하고, 바뀐 조건과 결과를 설명하기.
- 계획을 확정하고 지도에서 길을 확인한 뒤 숨맵에 돌아와 저장된 계획 이어가기.
- 오래된 데이터/후보 없음 중 하나를 보고 왜 진행되지 않는지와 다음 행동을 찾기.

기록: 완료/막힘 위치, 조작 도움 여부, 추천 이유 이해, 필수 고정과 혼잡 선호 차이 이해, 자료 시각을 현재 확정 사실로 오해했는지. 실제 관찰한 시간·발언만 기록하고 성공률/효과 수치를 만들지 않는다. 도움 없이 핵심 경로와 조건 변경을 이해하지 못한 부분은 수정 후 같은 과제를 다시 확인한다. 참여자를 확보하지 못하면 내부 접근성·휴리스틱 점검만 완료로 보고하고 ‘첫 사용자 검증 완료’로 표기하지 않는다.

## 사용자 확인 요청

구성안 자체 확인: 시작→출발역 선택→추천, 장소 고정→선택→확정 후 지도 버튼 노출을 브라우저에서 확인했다. 권한 거절·후보 없음·예측 공백·지연/오래된 자료·AI/TMAP/서울시 실패·선호 초과·저장 재방문 전환이 작동한다. 320/390px 설정에서 가로 넘침 없음, 데스크톱 2열 배치 확인, 콘솔 오류 없음. 예시 자료를 사용하는 화면 모형의 검증이며 실제 서비스 기능 검증 수치에 합산하지 않는다.
