## 두 방향

| 요소 | A. 서울 산책 안내서 | B. 저녁의 도시 지도 |
|---|---|---|
| 첫인상 | 밝은 종이, 숲색 글자, 산책 안내 페이지 | 짙은 녹색 도시 배경, 밝은 시각 숫자, 이동 전 확인 화면 |
| 타이포그래피 | Noto Serif KR 제목과 장소명, Noto Sans KR 설명 | Noto Sans KR 중심, 도착시각을 가장 크게 |
| 정보 순서 | 원래 계획·고정 → 작은 지도 → 장소 → 도착시각·변경 이유 | 큰 지도 → 원래 계획·고정 → 도착시각 → 장소·변경 이유 |
| 카드 성격 | 구분선과 여백으로 이어지는 편집면 | 배경과 구별되는 둥근 계획 카드가 실행 카드로 전환 |
| 지도 | 위치 확인을 돕는 작은 삽입 지도 | 도시의 윤곽과 선택 장소를 먼저 보는 넓은 지도 |
| 어울리는 강점 | 무엇을 유지했고 왜 바꾸는지 읽기 쉬움 | 어디로 언제 나가는지 빠르게 파악 |

**추천: A를 기본 방향으로.** ‘원래 계획을 가능한 한 유지한다’는 차이가 지도보다 유지/변경 설명에서 잘 드러난다. B는 위치와 도착시각의 비중을 높이고 싶을 때 적합하다. B를 단순 다크 모드로 취급하거나 두 안의 장식을 전부 섞지 않는다. 선택 후 같은 정보 구조로 시작·조건 수정·실행 및 데스크톱까지 확장한다.

## 동일한 검토용 데이터

모든 혼잡·인구·시각은 **만든 예시**다. 서울시 실시간 응답이나 실제 TMAP 이동시간이 아니다. 화면 위와 각 화면 아래에 검토용 표시가 있고, 공식 표본 표시에도 예시임을 적었다.

- 기준: 2026-09-19 17:55 KST 가정. 원자료 17:40, 수신 17:53, 비교 17:55.
- 원래 계획: 서울역 출발, 여의도한강공원 · 여의도안내센터, 18:20 도착, 60분 산책. 보통까지 선호, 최대 1시간 늦춤 허용.
- 이 샘플은 **방문 시각을 직접 정한 상황**이다. 지금 출발의 실제 ETA처럼 표현하지 않으며 가상의 이동 소요시간을 만들지 않는다. 정확한 시각 없이 시작하는 실제 흐름은 승인된 구성안에 그대로 남아 있다.
- 첫 결과: 장소를 유지하고 19:00으로 40분 늦춤. 19·20시 예시 공식 표본이 모두 보통이라는 근거.
- 18:20 고정 후 명시적으로 재비교: 도착시각을 유지하고 반포한강공원 · 반포안내센터로 변경.
- 장소와 시각 모두 고정: 여의도 18:20을 유지하고 선호 불충족으로 표시. 자동 해제·완화하지 않음.
- 상단 상태 선택은 검수 도구이므로 새 예시를 초기화한다. 실제 서비스에서 실패하면 조건을 초기화한다는 제안이 아니다.

## Design Spells에서 실제 검토한 3개 사례

1. [Waze의 대안 경로 전환, Spell 240](https://designspells.com/spells/smooth-transitions-when-viewing-alternative-routes-in-waze): 대안을 고르는 동안 지도와 경로 비교의 문맥이 이어지는 사례. 숨맵에는 **고정 조건 영역을 유지하고 변경된 장소/시각/이유만 전환**하는 방식으로 옮긴다. Waze의 경로 선·교통 표현은 가져오지 않는다. 숨맵 내부에 상세 경로가 없으므로 지도는 공원 위치와 집계 영역만 표시한다.
2. [(Not Boring) Weather의 시간 슬라이더, Spell 058](https://designspells.com/spells/hourly-weather-changes-visualized-via-a-time-slider-in-%28not-boring%29-weather): 시간 탐색과 해당 시점의 상태가 연결되는 사례. 숨맵에는 **도착~체류 종료 띠와 시간별 공식 표본을 함께 읽는 탐색**으로 적용한다. 3D 날씨·연속적인 배경 변화는 복제하지 않는다. 혼잡 단계는 이산 표본으로 남기고 예측 공백은 빗금/누락으로 표시한다.
3. [[untitled]의 형태 전환, Spell 257](https://designspells.com/spells/morphing-transitions-in-untitled): 선택한 요소가 확장된 화면으로 이어지는 사례. 숨맵은 **동일한 장소·도착시각을 남긴 카드 안에서 재확인 → 확정 → 지도 실행**으로 이어진다. 새 모달이나 길찾기 카드 여러 개를 만들지 않는다. 플레이어의 장식이나 효과를 복제하지 않는다.

세 사례의 페이지와 공개 재생 화면을 직접 확인했다. 아래 지속시간은 원본에서 측정한 값이 아니라 숨맵 검토안에 맞춘 설정이다. 외부 영상·이미지는 복사하지 않았다.

## 세 동작 샘플

### 1. 고정 → 다시 비교

‘18:20 고정’ → ‘이 조건으로 다시 비교’를 누른다. 고정 버튼은 같은 위치·DOM에 남고, 결과의 변경 부분만 약 320ms 이동/강조한다. 조정 후 재비교 전에는 계획 선택이 비활성화된다. 선택/확정 화면에서 고정 조건을 바꾸면 비교 화면으로 돌아와 재비교를 요구한다. 필수 조건과 혼잡 선호를 혼동하지 않는다.

### 2. 도착·체류 살펴보기

시간 슬라이더는 5분 단위로 로컬 표시만 바꾼다. 추천·고정된 도착시각에는 영향이 없다. 키보드 화살표로도 조작한다. 공식 시점에 정확히 맞으면 해당 표본과 인구 범위를 보여주고, 사이 시각이면 앞뒤 단계와 ‘숨맵 인구 추정 · 선형 보간’을 구분한다. 체류 띠는 방문 구간 표시이며 혼잡이 연속적으로 보장된다는 뜻이 아니다.

현재 관측은 사각 표식과 ‘현재 관측’, 공식 미래 표본은 원형 표식과 시각/단계, 가공 인구는 점선 상자와 추정 라벨로 구분한다. 19시 누락 예시에서는 18~20시 사이를 빗금과 누락 글자로 표시하고 인구 보간을 만들지 않는다. 공식 단계 사이를 부드러운 그래프로 연결하지 않는다.

### 3. 선택 → 확인 → 실행

‘이 계획 선택’ → ‘확인하고 계획 확정’으로 같은 카드의 내용이 전환된다. 장소와 도착시각 제목은 유지하며 높이 전환 약 300ms, 실행 내용 이동 약 260ms를 사용한다. 지도 버튼은 확정 후에만 나타난다. 포커스는 확인 버튼 → 네이버지도 버튼으로 이동하고 눈에 보이는 테두리를 유지한다.

길찾기 버튼에는 서울역과 선택한 안내센터가 이미 들어간다는 구성을 보여준다. **검토안 버튼은 외부 지도·위치 권한을 실제로 열지 않는다.** 실제 앱의 동일 accessPoint 사용, URL Scheme, 비용·재확인 규칙을 대체하거나 재검증했다고 주장하지 않는다.

## 실패 상태

| 예시 상태 | 같은 두 방향에 적용한 구성 |
|---|---|
| 예측 공백 | 누락 시각, 빗금 영역, 판단 보류 이유, 확정 동작 보류 |
| 혼잡 선호 불충족 | ‘참고 계획’과 선호 초과 설명. 고정 조건은 유지. 선택 확인 때도 제한 반복 |
| 이동시간 조회 한도 | 출발지·조건 유지 안내, 도착 시간대 직접 지정 대안 설명. 가짜 ETA/0분 표시 없음 |
| 위치 권한 거절 | 출발역 검색과 서울역 선택 샘플. 실제 권한 요청 없음 |

조회 한도에서 직접 시간대 입력까지의 전체 복구 화면은 이번 추천 화면 비교 범위에 포함하지 않았다. 승인된 전체 화면 통합 때 기존 수동 모드에 연결한다.

## 실제 수행한 검토안 검수

- 두 방향의 정상·공백·선호 불충족·한도·권한 거절 상태를 브라우저에서 확인. 서울역 선택으로 권한 거절 상태 복구 확인.
- 320 / 390 / 736px에서 가로 넘침 없음. 320px 시간축 첫 단계 문구 잘림을 수정하고 8개 표본 라벨의 카드 내부 표시를 확인.
- 고정 후 결과 변경, 두 조건 동시 고정의 선호 불충족, 재비교 전 선택 비활성화 확인. 고정 영역의 화면 내부 위치/높이 유지 확인.
- 슬라이더 화살표 한 번으로 5분 이동, 추천 시각은 그대로 유지. 공식 표본과 보간 인구를 구분.
- 두 안의 선택/확정 전환, 지도 버튼 노출 시점, 확인 버튼과 첫 지도 버튼의 포커스 이동 확인. 프로그램 포커스도 3px 테두리로 표시.
- 보이는 주요 버튼·범위 입력·검색·상태 선택 높이 44px 이상, 상세 펼치기도 44px. 모바일 터치 **영역 크기**를 확인했으며 실제 터치 기기 검증은 아니다.
- 색상 외 텍스트·고정 상태·원형/사각형·빗금/누락을 사용. 측정한 본문·보조 글자·주 버튼·경고 대비는 최소 5.71:1, 활성 컨트롤 경계 최소 3.33:1. 장식 구분선 및 비활성 컨트롤은 별도다. 전체 WCAG 인증을 의미하지 않는다.
- ‘동작 줄이기’에서 애니메이션 없음과 동일 결과/실행 카드 유지 확인. OS `prefers-reduced-motion`도 CSS와 JS 양쪽으로 처리. 실제 OS 설정 전환과 스크린리더 낭독은 미검증.
- 최종 스크립트 문법 검사 통과, 브라우저 콘솔 오류 없음. 네트워크 요청 코드·앱 API 호출·저장소/위치 접근 없음. 정적 서체와 D3 다운로드는 있다.
- 기존 앱의 117개 검사·타입·린트·빌드 결과는 재사용했다. 앱 코드가 바뀌지 않아 이번에 다시 실행하거나 실제 API를 재호출하지 않았다.

## 남은 승인과 검증

- **시각 방향 승인 대기**: A/B 또는 구체적인 조합 의견을 받은 후 실제 전체 UI에 적용한다.
- 실제 휴대폰 GPS 허용/거절, 카카오 실행, 지도 앱 미설치/복귀와 모바일 전체 흐름은 미완료다. 사용자가 확인한 네이버 연결 성공만 기존 기록으로 유지한다.
- TMAP 공개 운영 한도 미해결: 현재 Free 하루 10건, paid 전환 없음. 5곳씩 새 계산하면 매우 빠르게 소진된다. 시각 디자인으로 해결된 것으로 간주하지 않는다. 9/18의 6/10 기록을 9/19 잔량으로 재사용하지 않았으며 오늘 원장은 조회하지 않았다.
- 실제 첫 사용자 설명 없는 이해도 관찰 미완료. 디자인 적용 뒤 동일 핵심 흐름/실패 복구/처음 사용자 이해를 다시 확인한다.
- 원래 9/18 완성 목표는 이미 지났다. 후속 사용자 지시대로 디자인 방향 검수를 진행하며, 일정 때문에 승인 절차나 남은 기능 검증을 생략하지 않는다.
