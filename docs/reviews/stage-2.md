# 2단계 검수 보고 — 수동 조건과 추천 엔진

2026-09-17 · 상태: 구현·로컬 자체 검증 완료, 공개 Preview 배포 준비.

브랜치 `feat/recommendation-engine`. 배포 URL과 코드 버전은 공개 검증 뒤 기록한다.

## 완료한 것

- 원래 장소·도착 시각·체류시간, 허용 장소·도착 범위, 혼잡 선호, 변경 최소/덜 붐빔 우선 입력.
- 실제 제공된 장소×예측 시각으로 후보 생성. 필수 조건 유지, 최대 3개 비교 카드, 변경 내역·제외 이유·원자료 근거.
- 원래 계획 유지, 선호 미충족, 자료 부족, 예측 시각 없음, 조건 충돌을 구분.
- 지연 예측은 사용자가 직접 허용한 경우만 참고 비교. 60분 초과·대체 자료·수신 지연 자료는 제외.
- 조건 변경 시 이전 응답 차단, 입력 보존, 서버 검증, 기존 공개 데이터 캐시 재사용.

## 검증

- `npm run check`, `npm run build` 통과.
- `npm test` 41개 통과. 288개 조건 조합에서 필수 조건·최대 3장·중복 제거 확인.
- 모의 HTTP: 반복 비교의 원본 호출 수 5회 유지. 미지원 장소·큰 요청은 400.
- 모의 브라우저: 지연 동의 전/후, 정렬 모드 변경, 기준 계획 보존, 없는 16:30 예측 안내, 390px 입력·카드·넘침 없음. 콘솔 오류 없음.

## 비용·남은 범위

이번 단계 OpenAI **0회 / $0**. 누적 보수적 추정 **$0.000616**, 예산 기록 예약 **$0.05**, 전체 승인 **$20** 유지. 기존 Vercel Hobby·Preview 키·데이터 캐시를 사용한다. `main`과 Production은 변경하지 않는다.

자연어 AI는 3단계, 잠금 칩·선택 완료 등은 4단계, 시각 디자인은 6단계다. 실제 이동시간·소음·체류 내내의 혼잡을 보장하지 않는다. 추천 정책·예외·근거 구조는 [엔진 문서](../recommendation-engine.md)를 따른다.

## 사용자 검수

1. 원래 장소와 제공된 정시(예: 오늘 17:00)를 입력하고, 다른 공원 변경과 최대 1시간 지연을 허용한다.
2. 자료 지연으로 보류되면 내용을 확인하고 `지연 예측 참고 비교를 허용해요`를 선택해 다시 비교한다. 이 선택 전에는 자동으로 지연 자료를 쓰지 않는다.
3. ‘계획 변경 최소’와 ‘덜 붐빔 우선’을 비교한다. 원자료에 따라 추천이 같을 수도 있으며, 바뀌더라도 처음 입력한 원래 계획은 유지되어야 한다.
4. 원래 시각을 17:30으로 하고 ‘원래 도착 시각 그대로’를 선택한다. 그 시각 예측이 없다면 자동으로 17시나 18시를 추천하지 않아야 한다.

요청한 단계별 검수 방식에 따라 승인 후 **3단계: 자연어 조건 해석과 AI 설명 연결**을 진행한다.
