# 디자인 전 핵심 흐름 통합 검수

2026-09-18. 대상 앱 `c963000`, 문서 기준 `76b0e83`. [고정 Preview](https://soommap-review-yeongjis-projects-f12fc56b.vercel.app). **5단계 자체 완료를 전체 기능의 사용자 검수 완료로 취급하지 않는다.** 이번 승인은 통합 감사·차단급 수정·화면 구성 제안까지이며, 전체 UI 변경은 구성안 확인 후 진행한다.

## 결론과 판정 범위

확인 범위에서 추천 계산·필수 조건·자료 시각·비밀값·예산 제어를 깨는 차단급 코드 결함은 발견하지 않았다. 따라서 앱 코드·추천 정책·API 계약·배포를 변경하지 않았다. 새로 연결된 실제 AI+TMAP+서울시 흐름은 배포된 HTTP 엔드포인트와 현재 클라이언트의 순수 상태 함수로 확인했다. **실제 휴대폰에서 전체 여정을 한 번에 완료한 검증과는 다르다.**

가까운 도착시각을 덮는 예측이 없는 경우와 TMAP Free 공개 사용량은 제품 가용성의 남은 제한이다. 이를 성공한 추천으로 포장하거나 외삽·유료 전환으로 임의 해결하지 않는다. 모바일 장치 검증과 처음 쓰는 사람의 이해도 검증도 남아 있다.

## 이번 추가 검증

2026-09-18 17:01~17:05 KST, 현재 고정 Preview. 기존 계정/환경변수/배포 재생성 없음.

1. 서울역 공개 좌표에서 5곳 이동시간 요청 후 자연어를 실제 AI로 해석했다. 목적지·원래 시각 미정, 체류/제외/선호 보존은 통과했다. 결과 후보가 존재한다고 가정한 검사에서 중단했다. 첫 검사에서는 결과 상세를 보관하지 않아 정확한 제외 이유 전체를 사후 단정하지 않는다.
2. 직후 공개 자료에서 5곳 모두 원자료 16:30, 첫 예측 18:00, 수신 약 17:01임을 확인했다. 이 자료에서는 18시 이전 도착을 앞뒤 공식 예측으로 둘러쌀 수 없다. 이는 기존 ‘외삽하지 않음’ 정책의 실제 가용성 제한이다. 기존 단위검사도 같은 앞쪽 표본 누락을 추천 제외한다. 과거 관측을 미래 예측으로 섞지 않는다.
3. 반복적인 5곳 재호출 대신 공식 역 목록의 도봉산 7호선에서 반포 1경로만 확인했다. AI 호출 전에 실제 도착이 첫 예측 이후인지 검사했다. 여기서 실제 AI 해석→실제 예측·체류 평가→장소/시각 고정 재비교→선택 재확인→같은 출발/접근 지점 링크 생성이 통과했다. 나머지 경로를 조회하지 않은 사실을 추천 제외 사유로 유지했다.
4. 혼잡 선호 초과(`preference-unmet`)를 명시했고 고정 장소를 제외하자 `no-candidates`가 됐다. 조건을 몰래 풀지 않았다. 고정·재비교·선택은 기존 이동 토큰을 재사용했다.
5. 이번 검증은 휴대폰 앱을 새로 여는 검증이 아니다. 기존 네이버 사용자 확인 및 카카오 데스크톱 결과를 재사용했다. 사용자 브라우저의 저장 계획을 덮어쓰지 않았다.

프로젝트 `.local/stage-6-audit/`의 검사 결과는 로컬 임시 기록이며 Git에서 제외된다. 공급자 원문·세션 쿠키·서명 토큰·키는 문서/로그에 저장하지 않았다. 실제 자동 검증 117개 및 타입·린트·빌드는 코드가 같은 5단계 결과를 재사용했다.

| TMAP 예산 | free 10/day 원장 예약. 요청 차단 때 외부 호출 없음. paid 모드 비활성 | 유료 전환 없음 |

현재 발견한 가용성 제한 두 가지는 UI에 숨기지 않는다.

- **예측 시작 전 도착**: 추천할 수 없는 이유, 예상 도착과 첫 예측 시각을 나란히 보여주고 방문 시간대를 직접 고르는 대안을 제시한다. 시각 자동 이동·과거 관측 대입은 하지 않는다. 새 자체 예측 모델은 현재 범위 밖이다.
- **TMAP Free**: 이번 검증 후 장부 기준 오늘 6/10건 사용, 4건 남음. 새 출발지의 자연어 모드는 현재 5곳 계산을 요청하므로 남은 4건으로는 해당 새 계산이 차단된다. 실제 공개 이용량을 감당한다고 볼 수 없다. Free 안에서는 캐시 재사용·도착 시간대 직접 입력이 가능하다. 기존 안내 단가 0.55원/건이라면 5곳 약 2.75원이나 가입 조건은 전환 시 재확인한다. 과거 5,000원 승인만으로 paid를 켜지 않고 ‘나중에 전환’ 지시를 유지한다. 비용 부족 때문에 결과 정확도를 낮추지는 않는다.
