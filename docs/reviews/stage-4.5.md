## 구현

- 현재 위치·출발역 검색, 출발지 유지, 공원 표시 좌표와 안내센터 접근 좌표 분리.
- 지금 출발 기준 TMAP 대중교통 ETA → 도착/체류 구간 혼잡 정렬. 도보 포함, 시간 고정 충돌·누락·만료는 명시적으로 제외.
- 같은 출발지·접근 지점으로 최종 확정 후에만 네이버·카카오 길찾기 버튼. 네이버 모바일 scheme/설치 안내, 카카오 모바일 scheme/웹 링크.
- TMAP 총 5,000원 승인 반영. 요청 전 atomic 예약, 하루 한도·사용자/IP 제한·암호화 TTL 캐시·중복 방지. OpenAI 모델/최대 2회 구조 유지, 좌표는 AI에 전달하지 않음.
- 상세 동작·공식 근거·제한은 [이동 런타임](../mobility-runtime.md).

## 검증한 것

- 자동 검사 **108개 통과**. 타입·린트·프로덕션 빌드 통과.
- 기존 실제 Redis의 격리된 임시 키로 동시에 12개 요청을 보내도 남은 5원만 예약함. Free 10건, 사용자 3회/분, IP 6회/분, 장부 누락 시 차단 검증. 검사 키 삭제 완료.
- 로컬 HTTP에서 서명 세션·동일 출처 검사, 잘못된 좌표, 타 세션/조작 ETA 토큰 거부 확인.
- 모의 HTTP 공급자를 사용한 화면: 출발역 → 자동 ETA → 고정 재추천 → 선택 → 확정. 최초 TMAP 5건 뒤 고정·선택·확정은 TMAP/AI 0회 추가. 자연어 비교 모의 AI 2회.
- 추천·선택 중 지도 버튼 없음, 확정 후 출발·도착점 유지 확인. 실제 카카오 웹에서 서울역 1호선 → 반포안내센터와 대중교통 선택을 확인함. 공공 좌표만 사용.
- 모바일 폭 390 설정에서 입력/결과 확인, 가로 넘침 없음. 콘솔 오류 없음. TMAP 실패 시 후보를 만들지 않음.
- 실제 OpenAI/TMAP 호출 **0회**, 추가 비용 **0원/$0**. TMAP 실제 장부 초기 예약액 0원. 이전 OpenAI 예산 장부 미변경.

## 남은 확인과 사용자 작업

1. TMAP 계정에서 대중교통 요약 API 상품 설정 후 `.env.local`에 `TMAP_API_KEY`, `TMAP_BILLING_MODE` 저장. 종량제 사용 승인(총 5,000원)은 받았으며 승인을 다시 요청하는 것이 아님. 계정 약관·결제 상품 설정은 사용자 직접 작업.
2. 키 설정 후 공식 공공 출발역 1개 → 공원 1곳으로 실제 응답을 최소 호출 검증. Preview 환경변수만 추가하고 해당 배포를 최종 검수 URL로 갱신.
3. iOS/Android 실기기에서 네이버·카카오 설치/미설치 연결과 위치 권한 허용/거부를 사용자 검수. 데스크톱 검증을 모바일 앱 성공으로 간주하지 않음.

공개 Preview에서도 서울시 18:05 원자료의 19~20시 실제 예측으로 반포 계획을 확정하고, 서울역 출발을 유지한 양쪽 지도 버튼 및 콘솔 오류 없음을 확인했다. 모의 이동시간을 공개 서버에 표시하지 않았다.

[TMAP 설정 방법](../tmap-setup.md)

현재 링크에서는 TMAP 키가 없으면 자동 도착 계산을 연결 대기로 표시한다. 출발역 선택 → 도착 범위 직접 지정 → 비교/확정 → 지도 길찾기는 검수 가능하다. 준비되지 않은 실제 ETA를 모의값으로 대체하지 않는다.
