## 구현

- 현재 위치·출발역 검색, 출발지 유지, 공원 표시 좌표와 안내센터 접근 좌표 분리.
- 지금 출발 기준 TMAP 대중교통 ETA → 도착/체류 구간 혼잡 정렬. 도보 포함, 시간 고정 충돌·누락·만료는 명시적으로 제외.
- 같은 출발지·접근 지점으로 최종 확정 후에만 네이버·카카오 길찾기 버튼. 네이버 모바일 scheme/설치 안내, 카카오 모바일 scheme/웹 링크.
- TMAP 총 5,000원 예산 보호와 현재 Free 하루 10건 제한. 요청 전 atomic 예약, 사용자/IP 제한·암호화 TTL 캐시·중복 방지. OpenAI 모델/최대 2회 구조 유지, 좌표는 AI에 전달하지 않음.
- 상세 동작·공식 근거·제한은 [이동 런타임](../mobility-runtime.md).

## 검증한 것

- 자동 검사 **108개 통과**. 타입·린트·프로덕션 빌드 통과.
- 기존 실제 Redis의 격리된 임시 키로 동시에 12개 요청을 보내도 남은 5원만 예약함. Free 10건, 사용자 3회/분, IP 6회/분, 장부 누락 시 차단 검증. 검사 키 삭제 완료.
- 로컬 HTTP에서 서명 세션·동일 출처 검사, 잘못된 좌표, 타 세션/조작 ETA 토큰 거부 확인.
- 모의 HTTP 공급자를 사용한 화면: 출발역 → 자동 ETA → 고정 재추천 → 선택 → 확정. 최초 TMAP 5건 뒤 고정·선택·확정은 TMAP/AI 0회 추가. 자연어 비교 모의 AI 2회.
- 추천·선택 중 지도 버튼 없음, 확정 후 출발·도착점 유지 확인. 실제 카카오 웹에서 서울역 1호선 → 반포안내센터와 대중교통 선택을 확인함. 공공 좌표만 사용.
- 모바일 폭 390 설정에서 입력/결과 확인, 가로 넘침 없음. 콘솔 오류 없음. TMAP 실패 시 후보를 만들지 않음.
- 위 모의 검증까지 실제 OpenAI/TMAP 호출은 0회였다. 이후 아래 실제 연결 검증에서 TMAP 1회만 사용했다.

## Free 실제 연결 검증

- 사용자 키 설정 완료 및 Free 우선 선택을 반영했다. 기존 서울·OpenAI·Redis·Vercel 연결을 재사용했고 Production 환경변수는 변경하지 않았다.
- 공개 Preview에서 공공 출발역 서울역 1호선 → 반포안내센터 한 경로를 실제 TMAP으로 계산했다. 도착시각과 1시간 체류 구간의 서울시 혼잡 예측이 연결되고, 혼잡 선호를 넘는 경우 이를 명시함을 확인했다.
- 같은 화면에서 시각 고정 → 계획 선택 → 조건 확인 → 확정까지 완료했다. 출발지와 접근 지점이 유지된 네이버·카카오 길찾기 버튼, 콘솔 오류 없음을 확인했다.
- 실제 검증 전·후 Redis 장부는 당일 호출 예약 0 → **1건/10건**, 내부 보수적 비용 예약 0 → **1원**이었다. 따라서 고정·선택·확정의 추가 TMAP 호출은 **0회**다. Free이므로 이 검증의 유료 API 비용은 **0원**이며 내부 예약액은 청구액이 아니다.
- 실제 OpenAI 추가 호출 **0회/$0**. 앱 코드를 수정하지 않아 기존 108개 자동 검사 결과를 재사용했으며 새 Vercel 배포 빌드는 통과했다. TMAP 응답 원문·경로 수치·개인 위치는 검수 기록에 보관하지 않는다.

## 사용자 검수

1. 출발역 선택 → ‘지금 출발 · 대중교통 이동시간으로 계산’ → 비교 → 선택 → 확정 흐름을 확인한다. 무료 호출을 아끼려면 장소 변경을 끄고 공원 1곳으로 확인할 수 있다.
2. 휴대폰에서 현재 위치 허용·거부 후 안내, 확정 후 네이버·카카오 앱 연결을 확인한다. 설치되지 않은 경우 웹 또는 설치 안내가 표시되어야 한다. iOS/Android 실기기 동작은 아직 확인하지 않았으며 데스크톱 검증을 모바일 앱 성공으로 간주하지 않는다.
3. 확인 후 승인 또는 수정 의견을 받는다. 5단계는 아직 착수하지 않았다.

[TMAP 설정 참고](../tmap-setup.md). 현재 설정은 완료되어 재설정할 필요가 없다. Free 한도 소진 시 실제 ETA를 모의값으로 대체하지 않고 제한과 수동 도착시각 입력을 안내한다.

네이버 native scheme의 장소명 공백을 `%20`으로 통일한 후 관련 자동 검사 10개·타입·린트·빌드를 재검증했다. 문서 후속 커밋은 배포 동작을 바꾸지 않는다.
