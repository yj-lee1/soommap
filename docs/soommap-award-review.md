# 숨맵 — 수상 경쟁력과 사용자 니즈 검토

검토일: 2026-09-17 · 상태: 별도 검토안, 기존 기획에 미반영

기준 문서는 [기획안 v2](./soommap-hackathon-plan.md)다. 이번 요청에 따라 해당 파일은 수정하지 않았다. 아래에는 공개 자료에서 확인한 사실, 기획에 대한 판단, 추가 검증이 필요한 가설을 구분했다. 직접 사용자 인터뷰·사용성 테스트·경쟁 앱 설치 테스트를 수행한 결과는 아니다.

## 1. 판단

현재 기획은 신뢰할 수 있는 추천과 재계획의 구조가 구체적이다. 수상 경쟁력을 높이려면 다음을 더 증명해야 한다.

> 사용자가 이미 알고 있는 혼잡 정보를 다시 보여주는 것을 넘어, 실제로 실행할 수 있는 외출 결정을 더 쉽게 만들었는가?

가장 큰 부족함은 기능 개수보다 **사용자 문제의 빈도·강도, 이동 부담을 포함한 추천의 현실성, AI가 만든 개선의 증거**다. 지도·예측·PWA·3D를 추가하는 것만으로 이 세 가지를 입증할 수는 없다.

수상은 보장할 수 없지만, 현재 대회의 기획력·실현 가능성·확장성·AI 활용 적절성 기준에는 실제 사용자의 문제와 개선 전후를 보여주는 편이 직접 연결된다. [대회 공식 안내](https://static.wanted.co.kr/ai-championship/2026/landing.html)

## 2. 경쟁 환경에서 확인한 사실

아래는 공식 제품 설명·공개 페이지 확인이다. 소개된 기능의 실제 성능·만족도를 검증한 것은 아니며, 확인하지 못한 기능이 없다고 단정하지 않는다.

| 한강나우 | 11개 한강공원 혼잡·12시간 예측·주차·편의시설·현장 모드·이용규칙 소개 | 가장 직접적인 비교 대상. 한강 특화·예측 그래프·화장실 추가만으로 차별성을 설명하기 어려움 |

## 3. 사람들의 니즈: 확인된 신호와 가설

### A. 한산해도 멀면 가지 않을 수 있다

2024년 발행된 한강공원 접근성 연구는 2020년 서울시 이용자 조사 1,000명 중 829명을 실증분석했다. 공원까지의 평균 도달시간이 길수록 방문빈도가 감소하는 관계를 보고했다. 코로나 시기 자료이고 개인별 현재 이동 부담을 측정한 연구가 아니므로, 지금 사용자의 선호나 인과관계로 일반화하지 않는다. [연구 원문](https://kpaj.or.kr/_PR/view/?aidx=43596&bidx=3936)

제품상 추론: 여의도에서 난지로 바꾸는 일을 단순히 ‘장소 한 항목 변경’으로 계산하면 사용자의 실제 비용을 놓칠 수 있다. **추천할 수 있는 곳과 사용자가 실제 갈 수 있는 곳을 구분**해야 한다.

### B. 헛걸음의 원인은 혼잡도만이 아니다

미래한강본부의 2025 드론 라이트쇼 안내에는 우천 예보에 따른 취소, 주차·출차 제약, 나들목·역 출구 제한, 화장실 공사 안내가 함께 등장한다. 이는 당시 행사의 운영 사례이며 현재의 공원 상태나 소비자 선호 조사 결과가 아니다. [2025 공식 행사 안내](https://hangang.seoul.go.kr/www/eventMng/detail.do?evntSn=267&mid=538)

제품상 추론: ‘덜 붐비는가’와 함께 **실제로 방문할 수 있는지, 무엇을 확인해야 하는지**가 중요하다. 공원별 공식 공지 링크와 확인 시각만 있어도 사용자가 다음 행동을 할 수 있다. 공지를 수집하지 못한 상태는 ‘문제 없음’이 아니다.

### C. 공원 자체보다 그곳에서 하려던 일이 중요할 수 있다

2025년 한국관광공사 조사에 대한 정부 소개에서 방한 경험·체류 외국인 243명의 ‘주·휴식’ 관심 항목 중 한강·공원이 19%로 제시된다. 외국인의 일상 체험 관심을 보여주는 제한된 자료이며 한국 시민의 혼잡 회피 수요나 숨맵 이용 의사를 입증하지는 않는다. [정부의 조사 소개](https://www.korean-culture.org/koreanet/view.do?seq=1050604)

제품상 가설: 사용자는 한산한 장소 자체보다 강변 산책, 친구와의 만남, 피크닉, 특정 행사 같은 목적을 원할 수 있다. 특히 행사 관람이 목적이면 행사가 없는 공원으로 보내는 것은 문제 해결이 아니다. 이번에는 산책 범위를 유지하고 다른 목적을 요청했을 때 범위 밖임을 정확히 알려주는 편이 낫다.

### D. 동행인의 동의와 출발 직전 재확인이 필요할 수 있다

‘좋은 대안이어도 친구와 다시 합의해야 한다’, ‘아까 본 정보가 지금도 맞는지 궁금하다’는 것은 현재의 **미검증 가설**이다. 이번 조사에서 한국 한강 이용자를 대표하는 직접 근거를 확보하지 못했다. 짧은 인터뷰로 먼저 확인할 가치가 있다.

추천의 이후 단계로 계획 문구 복사·지도 연결·출발 전 재확인을 제안할 수 있다. 실제 이용 의향·반복 사용 빈도·지불 의사는 아직 모른다.

## 4. 수상을 위해 부족한 점

| 빈틈 | 예상 질문 | 보강 방법 |
|---|---|---|
| 누구에게 얼마나 절실한가 | “그냥 덜 붐비는 공원을 고르면 되는 것 아닌가?” | 최근 실제 외출에서 포기한 조건과 확인한 정보를 인터뷰로 확보 |

## 5. 추가·보강 아이디어 우선순위

아래 부담 평가는 기존 핵심 기능이 구현되었다는 가정의 상대 평가다. 외부 연동·데이터 정비가 필요한 항목은 코드 분량보다 실제 소요가 커질 수 있다. **전부 추가하자는 제안이 아니다.**

| 우선 | 아이디어 | 구분 | 해결하려는 문제 | 부담 | 판단 |
|---|---|---|---|---|---|
| 1 | ‘갈 수 있는 공원’ 선택 | 새 UX | 한산해도 갈 수 없는 대안 | 낮음 | 새 기능 하나를 넣는다면 우선 |
| 1 | 원래 계획과 추천의 차이 강조 | 기존 보강 | AI가 왜 이 안을 골랐는지 이해 안 됨 | 낮음 | 3D보다 먼저 완성 |
| 1 | 실제 사용자 비교 관찰 | 기존 검증 보강 | 효용을 증명하지 못함 | 모집에 좌우 | 제출 자료의 핵심 증거 |
| 2 | 조건 충돌 해결 제안 | 기존 보강 | 고정 조건을 모두 만족하는 안이 없음 | 낮음~중간 | 대표 시연 장면으로 적합 |
| 2 | 계획 문구 복사·지도 연결 | 새 완료 경험 | 동행인 합의·실제 이동으로 이어지지 않음 | 낮음 | 사용자 반응 확인 후 |
| 2 | 방문 전 확인 카드 | 새 정보 UX | 취소·출입 제한 등으로 헛걸음 | 낮음~중간 | 공식 링크부터, 자동 통제 판단은 이후 |
| 3 | 머무는 동안의 예보 변화 | 기존 그래프 확장 | 도착 순간만 보고 머무는 시간을 놓침 | 중간 | 실제 제공 시각의 표본만 비교 |
| 3 | 선택한 계획 다시 확인 | 기존 세션 기능 확장 | 출발 직전 조건 변화 | 중간 | 반복 사용 가설 검증용 |
| 이후 | 동행자 각각의 제약 조율 | 새 아이템 확장 | 서로 다른 출발지·시간·선호 조정 | 높음 | 공유 반응이 먼저 |
| 이후 | 외국인 외출 도우미 | 새 타깃 확장 | 언어·교통·현장 안내 이해 | 중간 이상 | 번역만으로 차별화되지는 않음 |

### 가장 먼저 제안하는 기능: 갈 수 있는 공원

‘다른 공원도 가능’ 옆에서 후보 5곳 중 실제 대체할 수 있는 곳을 고른다.

예시: **여의도·망원만 가능 / 반포·뚝섬·난지는 이번에는 제외**.

서버는 선택한 범위 안에서만 장소·시간을 비교하고, 더 한산한 다른 공원이 있어도 추천하지 않는다. 원문에 허용 장소가 있으면 AI가 요약하되 사용자가 확인할 수 있게 한다. 모르는 공원에는 위치 보기 링크를 제공한다.

이렇게 하면 새 경로 API 없이도 이동 부담의 일부를 사용자가 통제할 수 있다. 단, 실제 소요시간을 계산한 최적화는 아니다. 차후 출발역·교통수단·최대 이동시간을 넣으려면 실제 경로 데이터가 필요하다.

### 가장 강한 시연 후보: 조건 충돌을 풀기

설명용 시나리오:

- 사용자는 여의도와 17시를 고정하고, 덜 붐비기를 원한다.
- 주어진 예측에서는 그 조건을 충족하는 안이 없다.
- 숨맵은 ‘장소를 유지하면서 시간 변경을 허용하는 안’과 ‘시간을 유지하면서 장소 변경을 허용하는 안’을 **아직 적용되지 않은 제안**으로 보여준다.
- 사용자가 하나를 허용하면 실제 후보를 다시 계산한다.

숫자·공원 상태는 실제 시연 때의 데이터로 채운다. 이 흐름은 불가능한 요구를 그럴듯하게 만족했다고 말하지 않으면서, 사용자가 바꿀 수 있는 최소 조건을 찾는 모습을 보여준다. 기존 v2의 고정·해제·빈 결과 처리를 더 선명하게 시연하는 보강이다.

### 선택 완료를 실제 행동과 잇기

선택 완료 후 제공할 작은 행동은 ‘지도에서 위치 보기’와 ‘계획 문구 복사’다. 문구에는 장소·도착 시각·변경 이유·정보 확인 시각을 담고 사용자가 편집·전달하게 한다. 시스템이 대신 메시지를 발송하지 않는다.

만날 지점은 검증된 지도 지점 또는 사용자가 고른 지점만 사용한다. 혼잡 API의 대표 좌표를 실제 출입구나 만남 지점으로 둔갑시키지 않는다. 로그인·초대·공동 편집·투표는 별도 후속 기능이다.

## 6. 디자인에서 투자할 부분

### 추천의 차이를 첫 3초에 보이게

설명용 카드의 정보 순서는 다음과 같다. 아래 혼잡 상태는 가상 예시다.

```text
여의도 17:00 → 여의도 18:00
장소 그대로 · 1시간 늦게

약간 붐빔 → 보통  [서울시 예측]

유지하는 것: 공원, 산책 목적
바뀌는 것: 도착 시각
아직 모르는 것: 실제 이동시간

[17시 고정] [다른 선택 보기]
```

기술 용어·점수보다 무엇이 유지되고 무엇이 바뀌는지 먼저 읽히게 한다. 고정한 항목은 같은 위치에 남고 바뀐 항목만 짧게 강조한다. 설명 텍스트 전체를 매번 새로 읽게 하지 않는다.

### 편안한 인상과 명확한 상태

- 제품의 대표 색상은 차분하게 유지하고, 혼잡 단계에만 구분색을 쓴다. 화면 전체를 경고색으로 채우지 않는다.
- 선택한 한 안에 시각적 무게를 주고, 다른 안은 비교할 만큼만 노출한다.
- 현재·예측·미확인을 텍스트와 표시 형태로 구분한다. 오래된 값을 희미하게만 표시하면 놓치기 쉽다.
- 첫 화면은 사용자의 의도를 받는 공간이다. 시선이 계속 움직이는 입자·자동 지도 회전은 재계획 이해에 도움이 되는지부터 판단한다.
- 공원 사진은 장소의 분위기를 이해하는 보조 자료가 될 수 있지만, 최근 혼잡의 증거처럼 사용하지 않는다. 촬영 시점·이용권한이 확인되는 사진만 쓴다.

### 비교 방식을 테스트

세 카드, 원래 계획↔추천 비교, 장소×시간 작은 표 중 무엇이 빠르게 이해되는지는 아직 모른다. 내일까지 세 UI를 완성할 필요는 없다. 같은 가상 데이터를 넣은 간단한 화면 2개로 ‘무엇이 바뀌나요?’를 물어 더 잘 이해되는 구성을 선택할 수 있다.

3D는 첫인상 보강이다. 넓은 한강 전체 화면에서 효과가 작은 경우 선택 장소 확대에만 적용하고, 추천 카드의 읽기와 입력 속도를 해치지 않게 한다.

## 7. 타깃과 아이템 방향

우선 검증할 타깃은 **퇴근 후나 약속 전후, 이동 가능한 범위와 시간이 제한된 상태에서 산책하고 싶은 사람**이다. 이는 조사로 확정한 타깃이 아니라 이번 기능과 가장 맞는 가설이다. 성격 유형보다 구체적인 상황으로 사람을 모집하기 쉽다.

| 확장 방향 | 매력 | 지금 필요한 근거 |
|---|---|---|
| 제한된 시간의 개인 산책 | 원래 장소·시간 보존의 가치가 분명함 | 최근 실제 결정 사례와 반복 빈도 |
| 친구·연인의 약속 변경 | 공유와 조건 협상의 가치가 생김 | 누가 결정하고 무엇 때문에 합의가 늦어지는지 |
| 한강 피크닉 | 시설·그늘·돗자리·음식과 연결 가능 | 정확한 시설·이용 규칙 데이터, 경쟁 서비스 대비 개선 |
| 외국인 일상 체험 | 언어·현장 이해 지원으로 확장 가능 | 해당 사용자 인터뷰, 실제 교통·안내 이해 문제 |
| 아이 동반·이동 약자 외출 | 요구가 구체적일 가능성 | 직접 사용자 조사, 노면·경사·시설·동선 데이터 |

혼잡 데이터만으로 소음, 좌석, 접근성, 감각적 편안함을 대변하지 않는다. 여러 집단을 제출 소개에 나열하는 것보다 첫 집단의 문제를 해결한 증거가 더 설득력 있다.

사업화는 숙박·관광 서비스의 외출 계획 보조처럼 검토할 수 있지만, 구매 의사나 시장 규모는 확인하지 않았다. 심사에서 확장성을 말할 때는 같은 조건 모델을 다른 검증된 장소 데이터에 적용할 수 있다는 구조와 필요한 데이터 추가분을 설명하는 편이 낫다.

## 8. 내일 전에 수행할 작은 사용자 조사

### 10분 회고 인터뷰: 3~5명부터

실제로 최근 한 달 안에 한강이나 공원에 간 사람을 우선한다. 서비스 설명을 먼저 길게 하지 않고 최근 사건부터 묻는다.

1. 가장 최근에 언제, 누구와, 무엇을 하러 갔나요?
2. 장소와 시간을 어떻게 정했나요? 무엇을 어디서 확인했나요?
3. 예상보다 붐비거나 계획이 틀어졌던 순간이 있었나요? 실제로 무엇을 바꿨나요?
4. 바꿀 수 없었던 조건은 무엇이었나요? 이동·동행인·시간 중 어떤 것이었나요?
5. 다른 공원으로 바꾸는 것과 같은 곳에 늦게 가는 것 중 그 상황에서 어느 쪽이 가능했나요? 이유는 무엇인가요?
6. 마지막으로 결정을 내린 사람과, 일행에게 전달한 방식은 무엇이었나요?

‘혼잡 때문에 힘드시죠?’나 ‘이 앱 쓰고 싶으세요?’처럼 원하는 답을 유도하는 질문을 피한다. 인상적인 발언은 사용 동의를 받고 익명으로 인용한다. 인터뷰 요청·외부 전송은 이번 검토에서 수행하지 않았다.

### 비교 체험

같은 시각의 데이터와 비슷한 난도의 과제를 사용해 ‘혼잡 목록을 직접 비교’하는 방식과 숨맵을 비교한다. 사용 순서는 번갈아 제시해 학습 효과를 줄인다. 자체 목록을 비교 화면으로 만들었다면 경쟁 앱 테스트라고 표현하지 않는다.

관찰할 항목:

- 선택까지 걸린 시간, 포기·도움 요청 여부.
- 요청의 필수 조건을 놓친 횟수.
- 사용자가 무엇을 바꾸었는지와 왜 선택했는지 설명 가능한지.
- 선택한 안이 본인이 실제 갈 수 있는 곳인지.
- 다음 행동으로 지도나 계획 문구를 사용하는지.

소표본의 결과는 해당 참여자와 과제 범위로 보고한다. 예를 들어 실제 측정한 ‘5명 중 4명이 설명 없이 시간 고정을 사용’은 쓸 수 있지만 이를 시장 전체의 비율로 바꾸지 않는다. 지연시간·선택 시간·만족도 결과는 측정 전에는 쓰지 않는다.

### AI 역할의 검증

규칙 엔진은 LLM 없이도 후보를 정렬할 수 있어야 한다. AI의 가치는 자연어의 제약을 얼마나 정확히 읽고 정정 요청을 반영했는지, 설명이 의사결정에 도움이 되는지로 확인한다. 같은 후보 데이터에서 자연어 입력과 수동 조건 선택을 비교하면 AI의 추가 역할을 분리해서 볼 수 있다.

한국어 평가 문장 10~15개에 날짜·늦추기만 허용·장소 고정·지원 외 조건·상충 조건·정정을 포함한다. 조건 추출 정확성과 최종 Hard 위반을 구분해 기록한다. 코드가 위반을 막았다는 결과를 모두 LLM의 능력으로 보고하지 않는다.

## 9. 수상용 시연과 제출 증거

기능을 나열하는 데모보다 ‘문제 → 조건 충돌 → 사용자 허용 → 실행 가능한 변경안’의 흐름을 권한다.

1. 실제 사용자 회고에서 얻은 상황 하나를 소개한다. 확보 전에는 가상 상황이라고 표시한다.
2. 원래 계획·갈 수 있는 범위·고정 조건을 보여준다.
3. 단순 혼잡순으로는 부적절한 후보가 상위에 나올 수 있음을 같은 데이터로 비교한다.
4. 숨맵이 제약을 지키고 변경안을 설명하는 모습을 보여준다.
5. 시간 고정 등 조건을 바꾸고 결과의 달라진 부분을 확인한다.
6. 선택한 계획을 지도·복사 문구로 옮긴다.
7. 실제 수행한 사용자 관찰·평가 결과와 한계를 제시한다.

공개 심사에서 당일 모든 공원이 비슷하게 여유로울 수 있다. 라이브 기능과 별도로 시간·출처가 표시된 저장 시나리오 또는 명확한 예시 모드를 준비하면 차이를 설명하기 쉽다. 저장 자료를 현재 실시간 상태로 표시하지 않는다.

## 10. 우선 행동 제안

현재 기획은 유지한다. 다음 결정을 위한 제안 우선순위는 다음과 같다.

1. **직접 경험 3~5건 확인:** 실제 문제가 이동·시간·동행 중 어디에 있는지 확인한다.
2. **갈 수 있는 공원 범위:** 신규 기능 한 개를 고른다면 이 항목을 우선한다.
3. **원래 계획과 변경안의 비교 카드:** 기존 UX의 핵심을 시각적으로 완성한다.
4. **조건 충돌 시연과 검증 결과:** 기획력·AI 적절성의 증거를 만든다.
5. **남는 시간에 계획 복사·지도 연결:** 선택을 실제 행동으로 잇는다.

3D·새 데이터 소스·동행자 공동 편집은 이 우선순위 뒤에 둔다. 반응이 없는 니즈에 기능을 더하지 않고, 조사에서 반복되는 제약에 맞춰 다음 버전을 선택한다.
