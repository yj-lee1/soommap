# 1단계 데이터 기반

## 자료와 장소

서울특별시 실시간 인구데이터(citydata_ppltn)를 서버에서만 조회한다. 한 번의 응답은 한 장소다. 키 발급·기존 계정·배포 설정을 재사용하며 OpenAI는 이번 단계에서 호출하지 않는다.

| 장소 | 공식 코드 | 비교 그룹 |
|---|---|---|
| 여의도한강공원 | POI105 | hangang_walk |
| 반포한강공원 | POI095 | hangang_walk |
| 뚝섬한강공원 | POI093 | hangang_walk |
| 망원한강공원 | POI094 | hangang_walk |
| 난지한강공원 | POI090 | hangang_walk |

공식 API 응답의 이름·코드를 공식 영역 SHP와 대조했다. `src/lib/data/places.json`은 장소 ID·코드·그룹·활동·환경·표시점·영역 참조·공개 여부를 분리한다. 장소 ID는 자유 문자열이며 한강 전용 union이나 추천 로직은 없다.

`public/data/hangang-boundaries.geojson`은 서울시의 「서울시 주요 121장소 영역.zip」 중 5곳만 추출한 자료다. 공식 좌표계 WGS84를 유지하며 윤곽을 임의로 단순화하지 않았다. 표시점은 각 다각형 내부의 대표점을 계산한 것으로 입구나 만남 장소가 아니다. 지도 표현은 다음 기능 단계에서 진행한다.

출처·이용조건: [서울특별시 실시간 인구데이터](https://data.seoul.go.kr/dataList/OA-21778/A/1/datasetView.do), 공식 첨부파일 갱신일 2026-04-14, 공공누리 제1유형. 데이터는 추정 인구와 장소별 혼잡 지표이며 세부 산책로 혼잡·소음을 의미하지 않는다. [공식 안내](https://data.seoul.go.kr/dataVisual/seoul/guide.do)

공간자료 재생성은 `scripts/import-seoul-areas.py <공식 ZIP 경로>`를 사용한다. 개발용 Python 가상환경에 pyshp·shapely가 필요하며, 배포 앱의 의존성이 아니다. 변환 시 5개 코드·이름 일치와 도형 유효성·대표점 포함을 검사한다.

## 정규화·품질 정책

- 한국 시간 문자열을 명시적으로 UTC ISO 시각으로 변환한다. 잘못된 날짜·시각, 미래 관측 시각, 다른 장소 응답과 API 오류는 정상 스냅샷을 덮어쓰지 않는다.
- 현재 관측과 미래 예측을 분리한다. 알려지지 않은 혼잡 단계는 `null`/누락으로 처리하며 여유나 0명으로 바꾸지 않는다.
- 제공된 예측 표본만 보관한다. 중복은 정리하고 같은 시각의 상충 값은 제외한다. 보간·시간 반올림·자체 예측은 하지 않는다. 인원 범위가 잘못됐으면 범위만 표시하지 않는다.
- `FCST_YN=N`이면 미래 예측이 없는 상태다. `REPLACE_YN=Y` 또는 미상인 자료는 추천 가용 상태로 표시하지 않는다.
- 원자료 시각·수신 시각·화면 확인 시각은 서로 다른 값이다. 새로 조회했다는 이유로 오래된 원자료가 최신이 되지 않는다.
- **제품 내부 기준:** 자료 기준 시각에서 30분 이내는 최근, 30분 초과~60분은 지연, 60분 초과는 오래된 자료다. 지연·오래된 자료는 기준 시각과 함께 표시하고 최신 추천에서 제외한다. 공식 정확도 보증이나 갱신 SLA를 뜻하지 않는다.
- 캐시 수신 시각이 10분 넘게 지나면 갱신 지연을 따로 표시하고 추천 가용 상태에서 제외한다. 마지막 정상값을 표시할 수 있어도 최신 정보로 주장하지 않는다.
- 앞으로의 공통 예측 시각은 실제 5개 목록의 교집합이다. 이 교집합과 자료 신뢰성이 모두 충족돼야 `comparisonReady=true`다. 실제 추천은 2단계에서 구현한다.

## 서버리스 캐시·실패 처리

1. 요청이 들어왔을 때만 조회한다. 상시 프로세스·Cron·자동 폴링을 추가하지 않는다.
2. 표준 Next.js `unstable_cache`에 정규화된 공개 스냅샷을 5분간 재사용한다. Vercel Hobby의 기존 Data Cache를 사용하며 별도 유료 저장소를 만들지 않는다.
3. 페이지와 `/api/places`는 같은 캐시 식별자를 사용한다. 명시적인 이름공간·스키마 버전·공개 장소 ID만 키에 사용한다. 함수 직렬화가 경로별 빌드에 따라 달라지지 않도록 bound callable을 사용한다.
4. `connection()`으로 요청 시 렌더링하되, 명시적 데이터 캐시까지 우회하는 `force-dynamic`은 사용하지 않는다. 페이지 전체를 캐싱해 오래된 상태 표시를 숨기지 않는다.
5. 동일 worker의 장소별 동시 조회를 하나로 합친다. 정상 반환 후 5초 동안은 공유 캐시 쓰기가 끝나기 전의 인접 요청도 합친다. 실패하면 30초 동안 같은 worker에서 재시도를 쉬며 자동 재시도하지 않는다.
6. 각 원본 요청은 최대 8초, 5곳을 병렬 조회한다. 한 장소 오류 때문에 나머지 자료를 버리지 않는다. 첫 자료가 없으면 그 장소를 `자료 없음`으로 표시한다.
7. 갱신 실패 시 Next.js Data Cache의 마지막 정상 스냅샷을 유지한다. 원시 오류·키 포함 URL은 로그에 전달하지 않는다. Next가 출력하는 오류도 고정된 비밀값 없는 메시지만 포함한다.

Data Cache는 재배포 뒤에도 재사용할 수 있지만 영구 데이터베이스가 아니다. 캐시 퇴거나 새 호스팅으로 이전해 자료가 없으면 원본을 다시 읽으며, 그것도 실패하면 자료 없음으로 처리한다. 여러 worker/지역이 동시에 cold miss를 내면 제한적인 중복 원본 조회가 가능하다. 프로세스 내부 병합을 분산 락이라고 주장하지 않는다.

기본 5분 간격으로 5곳에 계속 트래픽이 있을 때는 한 캐시 기준 최대 약 1,440회/일 원본 조회가 가능하다. 실제로는 방문이 없으면 조회하지 않는다. 발급 키의 한도는 별도 공급자 설정이며 429·오류 시 재시도 폭주를 만들지 않는다. 사용량이나 한도 때문에 핵심 품질 변경이 필요하면 사용자에게 먼저 보고한다.

서버 설정 `DATA_CACHE_NAMESPACE`는 기본 `soommap-seoul-live-v1`, `DATA_CACHE_SECONDS`는 기본 300, 허용 30~300초다. 운영에서는 기본값을 유지한다. 모의 통합검사는 `fixture-` 이름공간과 30초를 사용해 실제 캐시를 오염시키지 않는다. Preview/Production 캐시는 Vercel에서 분리되며, 다른 호스팅의 다중 인스턴스 운영은 Next.js cache handler에 공유 저장소를 연결하는 어댑터로 이전한다.

공식 근거: [Next.js Data Cache API](https://nextjs.org/docs/app/api-reference/functions/unstable_cache), [요청 시 렌더링](https://nextjs.org/docs/app/api-reference/functions/connection), [Vercel Data Cache 동작·환경 분리·퇴거](https://vercel.com/docs/caching/runtime-cache/data-cache).

## 비용과 검증 경계

- 1단계 OpenAI 추가 요청/비용: **0회 / $0**. 0단계 추정 $0.000616와 예약 $0.05를 그대로 유지한다.
- `npm test`는 고정된 공개 fixture와 주입한 모의 통신을 사용한다. 실제 API는 장소 등록 검사와 배포에서 새 기능을 검증하는 경우만 사용한다.
- 모의 서버 helper는 `tests/fixtures/mock-seoul.mjs`, 상태·호출 횟수는 `.local/stage-1/`이다. 앱에서 import하지 않으며 배포 소스에서도 제외한다.
- 공유 Data Cache는 공개 장소 자료 전용이다. 사용자 입력·AI 결과·비용 원장은 넣지 않는다. 3단계의 전체 $20 강제 관리는 원자적 예약이 가능한 영속 저장소가 필요하며, 그 시점에 무료 범위와 운영 선택을 보고한다. 비용 변수나 프로세스 메모리를 전역 예산 차단으로 간주하지 않는다.
